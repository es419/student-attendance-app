# נוכחות+

אפליקציית PWA סטטית למעקב נוכחות, שעות ושכר משוער.

## מבנה

- `index.html` — מבנה המסך בלבד.
- `styles.css` — כל העיצוב.
- `calc.js` — חישובי שעות ושכר (לוגיקה טהורה, בלי DOM ובלי רשת), עם בדיקות ב-`tests/`.
- `app.js` — Supabase, נוכחות, מסכים, ייצוא והגדרות.
- `vendor/` — ספריות צד שלישי מקומיות (Supabase ו-XLSX), בלי תלות ב-CDN.
- `sw.js` — cache, offline shell והתראות push.
- `manifest.json` — הגדרות PWA.

## בדיקות

```powershell
npm test
```

הבדיקות מכסות את חישוב השעות והשכר (רגילות, 125%, 150%, תקרה, הפסקות, מחלה, משמרת לילה, משמרת שנשכחה).
הן רצות גם אוטומטית ב-GitHub Actions בכל push.

## התנהגות משמרות

- משמרת שחוצה חצות (למשל 22:00–06:00) נשמרת ומחושבת נכון.
- משמרת פתוחה מעל 16 שעות נחשבת "נשכחה": האפליקציה (והבוט) לא מנחשים שעת יציאה, אלא מבקשים להזין אותה או לבטל.
- שעת הכניסה, ההפסקה והיציאה נקבעת ברגע הלחיצה, לא אחרי סיום הבקשה לרשת.
- כל עריכה קוראת קודם את הנתונים העדכניים מהשרת, כדי לא לדרוס שינוי מטלגרם או ממכשיר אחר.
- מחיקת יום ניתנת לביטול למשך כמה שניות.

## הרצה מקומית

```powershell
py -m http.server 8000
```

ואז לפתוח `http://localhost:8000`.

## טעינה

יש שכבת loading חוסמת אחת בלבד:

- אם קיים snapshot מקומי, המסך מוצג מיד והסנכרון מול Supabase מתבצע ברקע.
- אם אין snapshot, הלוגו נשאר רק עד שהבקשה הראשונית ל-Supabase מסתיימת.
- אין timeout מלאכותי ואין spinner נוסף בתוך המסך.

## Telegram companion

הפרויקט כולל בוט Telegram שמתחבר לאותו חשבון ואותם נתוני נוכחות.

הבוט תומך בכניסה, יציאה, יציאה/חזרה מהפסקה, סטטוס נוכחי, סיכום היום ודוח החודש. החיבור לחשבון נעשה באמצעות קוד חד-פעמי מהגדרות האפליקציה.

### התקנה ב-Supabase

1. הרץ את המיגרציה שב-`supabase/migrations/20260918_add_telegram_companion.sql`.
2. הגדר Secrets לפונקציה: `TELEGRAM_BOT_TOKEN` ו-`TELEGRAM_WEBHOOK_SECRET`.
3. פרוס את `supabase/functions/attendance-telegram` ללא JWT verification.
4. הגדר את webhook של Telegram לכתובת הפונקציה עם אותו `secret_token`.

לא שומרים Bot Token בקוד או ב-Git.

## אבטחה

- האפליקציה מתחברת עם המפתח הציבורי של Supabase, ולכן **ה-RLS הוא ההגנה היחידה על הנתונים**.
  ב-`supabase/migrations/20260929_core_tables_rls.sql` יש הגדרות ל-`kv_store`, `push_subscriptions` ו-`break_reminders`.
  בדוק בדשבורד אם הן כבר מופעלות, ואם לא — הרץ את הקובץ.
- ה-webhook של Telegram נסגר כברירת מחדל: בלי `TELEGRAM_WEBHOOK_SECRET` הפונקציה מסרבת לכל בקשה.
- ביציאה מהחשבון נמחק הסנאפשוט המקומי של נתוני השכר.

## תכנון עבודה ותחזית

במסך "היום" נפתח "תכנון ימי העבודה": יעד נפרד מתקרת התשלום (ברירת מחדל 120), שעות לכל יום בשבוע וחריגים לחודש הנבחר. מכניסים שעות שייספרו לאחר ניכוי הפסקות. 0 מבטל יום, ושדה חריג ריק מחזיר את ברירת המחדל השבועית. חגים וחופשות אינם מזוהים אוטומטית.

התחזית מחברת רישומים קיימים עם תכנון להיום ולעתיד. רישום בפועל מחליף תכנון לאותו יום, ימים שחלפו ללא רישום אינם נספרים, ומשמרת פעילה נאמדת לפי הגבוה מבין התכנון והשעות שנצברו (כולל כללי ההפסקה). משמרת שנשכחה מחייבת תיקון ואינה נאמדת. השעות המתוכננות לא נכנסות לשכר או לייצוא נוכחות.

`planner.js` מכיל את החישוב הטהור ו־`planner-ui.js` את הכרטיס והטופס. התכנון נשמר ב־`settings.workPlan` באותו חשבון Supabase; אין צורך במיגרציה. שבוע ויעד משותפים לכל החודשים, חריגים מוגדרים לפי תאריך. השמירה קוראת תחילה את ההגדרות העדכניות, מאשרת הצלחה רק אחרי כתיבה, ומשאירה טיוטה בטופס במקרה כשל. כמו שאר השמירות מבוססות kv_store, עריכות בו־זמניות ממש אינן טרנזקציה אטומית.

בכניסה המהירה נשמרה לחיצה ארוכה, נוספו התכנון להיום, חיווי שמירה ונעילת הכפתורים עד סיום הפעולה, ותמיכה בהפעלת הכפתור עם מקלדת או טכנולוגיה מסייעת.

## שיבוצי קבלת קהל

במסך היום מופיעה שורה קומפקטית **קבלת קהל**. פותחים אותה, בוחרים תאריך ושיבוץ ושומרים. אין שיבוץ אוטומטי ביום שני, רביעי או בכל יום אחר, ואין חזרה שבועית. אפשר לבחור כל תאריך עתידי, גם בחודש הבא, ולשנות או לבטל שיבוץ קיים.

- בוקר: תזכורת לבוש והתארגנות ב־07:00 ויציאה ב־07:30, לקראת הגעה עד 08:30.
- אחר הצהריים (15:00–18:00): תזכורת לבוש בלבד, בלי דרישת הגעה ב־08:30.
- ב״שעות התזכורות״ משנים את שעת ההתארגנות, זמן הנסיעה ומרווח הביטחון. שעת היציאה מחושבת אוטומטית: 08:30 פחות הנסיעה והמרווח. אפשר לכבות תזכורות לשיבוץ מסוים.

צריך להפעיל התראות פוש במכשיר שבו רוצים לקבל אותן. באייפון משתמשים באפליקציה שנוספה למסך הבית. האפליקציה אינה מבקשת הרשאה אוטומטית. חסימה או העדר הרשאה מוצגים בטופס; שמירת שיבוץ לבדה אינה נותנת הרשאת התראות.

השיבוצים נשמרים בחשבון ב־`kv_store` במפתח נפרד לכל תאריך (`reception:YYYY-MM-DD`), בלי שינוי לנוכחות, לשכר או לתכנון השבועי. התזכורות מתוזמנות מראש ב־`break_reminders`, דרך אותו מנגנון cron ופוש שכבר משמש לתזכורות הפסקה ויציאה. אין צורך במיגרציה או בפריסת פונקציה חדשה. כל הזמנים לפי `Asia/Jerusalem`, לרבות שעון קיץ.

לכל תאריך וסוג תזכורת יש UUID יציב לפי החשבון, למניעת כפילות ברענון או בתזמון מקביל. שינוי שיבוץ מעדכן רק תזכורות שטרם נשלחו; ביטול מסיר את התזכורות הממתינות שלו בלבד. תזכורות שנשלחו אינן מופעלות מחדש, ושעות שכבר חלפו אינן נשלחות בדיעבד. כניסה למשמרת באפליקציה מבטלת את תזכורות קבלת הקהל שנותרו לאותו היום. פתיחת האפליקציה מחדש קוראת את השיבוצים העדכניים לפני סנכרון התזכורות. כשל בשמירה או בתזמון מוצג בטופס ומשאיר אפשרות לניסיון חוזר.

כמו שאר השמירות ב־`kv_store`, עריכות בו־זמניות של אותו תאריך אינן טרנזקציה אטומית; תאריכים שונים נשמרים בנפרד. הבדיקות מכסות תאריכים מפורשים בלבד, בוקר/אחר הצהריים, שעון ישראל וקיץ, זמנים שחלפו, תזמון חוזר, שינוי וביטול, כשל רשת ובידוד מתזכורות אחרות. משלוח פוש בפועל תלוי במנגנון הפוש הקיים, בהרשאות ובחיבור המכשיר.
