# נוכחות+

אפליקציית PWA סטטית למעקב נוכחות, שעות ושכר משוער.

## מבנה

- `index.html` — מבנה המסך בלבד.
- `styles.css` — כל העיצוב.
- `calc.js` — חישובי שעות ושכר (לוגיקה טהורה, בלי DOM ובלי רשת), עם בדיקות ב-`tests/`.
- `app.js` — Supabase, נוכחות, מסכים, ייצוא והגדרות.
- `vendor/` — ספריות צד שלישי מקומיות (Supabase ו-XLSX), בלי תלות ב-CDN.
- `sw.js` — cache, offline shell והתראות push.
- `manifest.json` — הגדרות PWA.

## מה חדש בגרסה 18

- אייקוני SVG במקום אימוג'י, נקודה פועמת וטיימר גדול במשמרת פעילה, כרטיס נטו בולט.
- אנימציות: מעבר חלק בכניסה/הפסקה/יציאה, מחוון טאבים נע, חלון הוספת יום עולה, ספירת מספרים, כניסה מדורגת של הרשימה והלוח, החלקה למחיקה.
- לוח עם צבע לפי כמות השעות; הערה ותגית ("מהבית", "בחג") לכל יום, כולל בייצוא לאקסל.
- טאב "סיכום": שעות לפי חודש, ממוצע שעות ליום, שעות כניסה ויציאה ממוצעות.
- קיצורי דרך על האייקון (אנדרואיד): `?action=clockin` ו-`?action=clockout`. הם רק מסמנים את הכפתור, האישור נשאר בלחיצה ארוכה.
- הגדרות מקובצות לפי נושא, צבעים שמתחשבים בצבע הדגש, צל עדין במצב בהיר.
- ניקוי: כללי עיצוב כפולים אוחדו, הוסרו קבצים מיותרים והתווסף `.gitignore`.

## גרסה 19: תחושת אפליקציה מקורית

- גופן עברי Heebo מקומי (בלי CDN, נשמר ל-offline), מספרים ברוחב קבוע.
- חלון הוספת היום הוא גיליון תחתון עם ידית, נסגר בגרירה כלפי מטה או באנימציה.
- החלקת שורה לצד המחיקה (במגע), רענון במשיכה כלפי מטה, פס התקדמות עליון במקום מסך טעינה בחילוף חודש ובפעולות משמרת.
- מצב ריק עם איור וכפתור, תחושת לחיצה קפיצית, בלי בחירת טקסט מקרית.

## גרסה 20: תיקוני שמירה ואמינות

- רישום קיים ליום חוסם כניסה מהירה נוספת, באפליקציה ובקוד בוט Telegram. כרגע נשמר רישום אחד ליום; שינויים עושים דרך עריכת היום.
- החתמת יציאה משמרת הערות ותגיות, ומסרבת לדרוס רישום של משמרת אחרת או יום מחלה.
- כשל בסגירת המשמרת בענן משאיר אותה פעילה ומאפשר ניסיון חוזר, בלי הודעת הצלחה שגויה.
- ממוצע שעות ליום עבודה אינו כולל שעות מחלה. כשל בטעינת סיכום מציג שגיאה וכפתור ניסיון חוזר.
- תיקון מחיקה בהחלקה, ביטול מחוות ללא מחיקה, ושחזור שלא דורס רישום חדש שנוצר בינתיים.
- מעבר חודש מחליף נתונים רק אחרי טעינה מוצלחת; רענון שנכשל אינו מציג הודעת הצלחה, ותשובות ישנות לחשבון או חודש אחרים נזנחות.
- הגדרות נערכות בטיוטה; כשל שמירה שומר את הטופס פתוח, וכתיבה משמרת את תכנון העבודה העדכני מהשרת.
- לוח השנה מוצג גם בחודש ריק. נוקו גם קובצי מצב זמניים של Supabase ממעקב Git.

## גרסה 21: מסך יום נקי יותר

בגרסה 21 הוסר הצפי החודשי ממסך היום. עריכת תכנון ימי העבודה נמצאת בהגדרות, ושעת היציאה לפי התכנון נשארה זמינה במשמרת פעילה. בתחתית ההגדרות מופיע מספר הגרסה לזיהוי עדכון שהותקן.

## בדיקות

```powershell
npm test
```

הבדיקות מכסות את חישוב השעות והשכר (רגילות, 125%, 150%, תקרה, הפסקות, מחלה, משמרת לילה, משמרת שנשכחה).
נוספו בדיקות לרישומים קיימים, הערות ותגיות, כשלים וניסיונות חוזרים, ממוצעי הסיכום, החלפת חודשים וחשבונות, הגדרות, מחוות וקוד פעולות הבוט.
הן רצות גם אוטומטית ב-GitHub Actions בכל push.

## התנהגות משמרות

- משמרת שחוצה חצות (למשל 22:00–06:00) נשמרת ומחושבת נכון.
- משמרת פתוחה מעל 16 שעות נחשבת "נשכחה": האפליקציה (והבוט) לא מנחשים שעת יציאה, אלא מבקשים להזין אותה או לבטל.
- שעת הכניסה, ההפסקה והיציאה נקבעת ברגע הלחיצה, לא אחרי סיום הבקשה לרשת.
- עריכות באותו טאב מבוצעות בתור וקוראות תחילה את הנתונים העדכניים מהשרת. כתיבה בו-זמנית ממש ממכשירים שונים עדיין אינה טרנזקציה אטומית; אין כאן שינוי בסכמת מסד הנתונים.
- מחיקת יום ניתנת לביטול למשך כמה שניות.

## הרצה מקומית

```powershell
py -m http.server 8000
```

ואז לפתוח `http://localhost:8000`.

## טעינה

יש שכבת loading חוסמת אחת בלבד:

- אם קיים snapshot מקומי, המסך מוצג מיד והסנכרון מול Supabase מתבצע ברקע.
- אם אין snapshot, הלוגו נשאר רק עד שהבקשה הראשונית ל-Supabase מסתיימת.
- אין timeout מלאכותי ואין spinner נוסף בתוך המסך.

## Telegram companion

הפרויקט כולל בוט Telegram שמתחבר לאותו חשבון ואותם נתוני נוכחות.

הבוט תומך בכניסה, יציאה, יציאה/חזרה מהפסקה, סטטוס נוכחי, סיכום היום ודוח החודש. החיבור לחשבון נעשה באמצעות קוד חד-פעמי מהגדרות האפליקציה.

### התקנה ב-Supabase

1. הרץ את המיגרציה שב-`supabase/migrations/20260918_add_telegram_companion.sql`.
2. הגדר Secrets לפונקציה: `TELEGRAM_BOT_TOKEN` ו-`TELEGRAM_WEBHOOK_SECRET`.
3. פרוס את `supabase/functions/attendance-telegram` ללא JWT verification.
4. הגדר את webhook של Telegram לכתובת הפונקציה עם אותו `secret_token`.

שינוי קוד הבוט ב-GitHub אינו פורס אוטומטית את פונקציית Supabase. כדי להפעיל את תיקוני הבוט בגרסה 20 יש לפרוס שוב את `attendance-telegram`; האפליקציה הסטטית אינה דורשת מיגרציה חדשה.

לא שומרים Bot Token בקוד או ב-Git.

## אבטחה

- האפליקציה מתחברת עם המפתח הציבורי של Supabase, ולכן **ה-RLS הוא ההגנה היחידה על הנתונים**.
  ב-`supabase/migrations/20260929_core_tables_rls.sql` יש הגדרות ל-`kv_store`, `push_subscriptions` ו-`break_reminders`.
  בדוק בדשבורד אם הן כבר מופעלות, ואם לא — הרץ את הקובץ.
- ה-webhook של Telegram נסגר כברירת מחדל: בלי `TELEGRAM_WEBHOOK_SECRET` הפונקציה מסרבת לכל בקשה.
- ביציאה מהחשבון נמחק הסנאפשוט המקומי של נתוני השכר.

## תכנון ימי עבודה ושעת יציאה

בהגדרות נפתח "תכנון ימי העבודה": יעד נפרד מתקרת התשלום (ברירת מחדל 120), שעות לכל יום בשבוע וחריגים לחודש הנבחר. מכניסים שעות שייספרו לאחר ניכוי הפסקות. 0 מבטל יום, ושדה חריג ריק מחזיר את ברירת המחדל השבועית. חגים וחופשות אינם מזוהים אוטומטית. הצפי החודשי אינו מוצג בממשק.

שעת היציאה במשמרת פעילה מחושבת לפי שעות התכנון לאותו יום, כולל ניכוי הפסקות מעבר למכסה הפטורה. השעות המתוכננות אינן רישום נוכחות ואינן נכנסות לשכר או לייצוא.

`planner.js` מכיל את החישוב הטהור ו־`planner-ui.js` את טופס ההגדרות ואת רמזי המשמרת. התכנון נשמר ב־`settings.workPlan` באותו חשבון Supabase; אין צורך במיגרציה. שבוע ויעד משותפים לכל החודשים, חריגים מוגדרים לפי תאריך. השמירה קוראת תחילה את ההגדרות העדכניות, מאשרת הצלחה רק אחרי כתיבה, ומשאירה טיוטה בטופס במקרה כשל. כמו שאר השמירות מבוססות kv_store, עריכות בו־זמניות ממש אינן טרנזקציה אטומית.

בכניסה המהירה נשמרה לחיצה ארוכה, נוספו התכנון להיום, חיווי שמירה ונעילת הכפתורים עד סיום הפעולה, ותמיכה בהפעלת הכפתור עם מקלדת או טכנולוגיה מסייעת.
